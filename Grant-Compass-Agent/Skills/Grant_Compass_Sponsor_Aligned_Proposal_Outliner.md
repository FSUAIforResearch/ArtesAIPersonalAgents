# Sponsor-Aligned Proposal Outliner

## When to Apply This Skill

Apply when the user types `/outline-proposal` or asks for a proposal outline, section prompts, page allocation, or review-criteria crosswalk. Follow the workflow below and end with three prioritized next actions.

## Objective

Create an editable proposal outline for one verified funding opportunity. Mirror the sponsor's required structure, connect proposal sections to published review criteria, and insert clear placeholders for project information the user has not supplied.

Use this Skill when a user asks to:

- Create a proposal outline.
- Organize an application around sponsor requirements.
- Map proposal sections to review criteria.
- Build a writing plan from a solicitation.
- Create section prompts or drafting questions.
- Identify what evidence belongs in each proposal section.
- Turn a verified opportunity brief into a proposal framework.

Do not use this Skill for broad funding discovery, final opportunity verification, final eligibility decisions, budget approval, compliance determinations, institutional commitments, or submission.

## Required inputs

Use a verified funding opportunity record, official solicitation, or opportunity brief containing as many of these facts as possible:

- Sponsor and program title.
- Opportunity number.
- Current solicitation and amendments.
- Required narrative sections.
- Required forms and attachments.
- Page, word, or character limits.
- Formatting requirements.
- Review criteria and weights.
- Program purpose and priorities.
- Eligibility and application limits.
- Award range and project period.
- Required partners, populations, settings, methods, outcomes, or plans.

Use any project information supplied by the user, such as:

- Working title.
- Problem or need.
- Objectives or aims.
- Methods or activities.
- Population, setting, or geography.
- Expected outcomes and impact.
- Team and partners.
- Preliminary evidence.
- Evaluation approach.
- Dissemination or sustainability approach.
- Budget assumptions.
- Facilities, equipment, or institutional resources.

If the opportunity has not been verified, use or request the Funding Opportunity Verifier workflow before creating a detailed outline.

## Required knowledge and tools

Consult:

- Current official sponsor solicitation.
- Controlling amendments, corrections, and FAQs.
- Current sponsor application guide incorporated by the solicitation.
- Verified opportunity brief.
- Uploaded Grant Compass knowledge packets:
  - `01_fsu_routing.md`
  - `02_match_rubric.md`
  - `03_output_templates.md`
  - `04_source_registry.md`

Use current FSU websites or files for institutional requirements. Do not pull institutional facts from an old example proposal when a current authoritative FSU source is available.

## Source hierarchy

Use information in this order:

1. Current program-specific solicitation and amendments.
2. Current program-specific FAQs and sponsor notices.
3. Current sponsor-wide application instructions incorporated by reference.
4. Current official FSU policy and institutional guidance.
5. User-supplied project facts.
6. Recommendations, clearly labeled as recommendations.

Do not allow a successful prior proposal, sample application, general grant-writing guide, API summary, or search result to override current instructions.

## Workflow

### Step 1: Confirm source control

Record:

- Sponsor.
- Program title.
- Opportunity number.
- Solicitation version or date.
- Amendments and FAQs reviewed.
- Application guide used.
- Official source URLs.
- Verification date.

If current instructions cannot be verified, create only a provisional outline and state the limitation prominently.

### Step 2: Extract the required application structure

Identify every required or conditional:

- Narrative section.
- Subsection.
- Form.
- Attachment.
- Letter.
- Plan.
- Certification.
- Appendix.
- Supplement.
- Preapplication element.

For each component, record:

- Exact sponsor title.
- Whether it is required, conditional, or optional.
- Page, word, or character limit.
- Formatting requirement.
- File format.
- Source location.
- Whether the component is scored or reviewed.

Preserve the sponsor's section names and order when they are specified.

Do not create required sections that are not supported by the current sources.

### Step 3: Extract review criteria

Capture:

- Scored review criteria.
- Subcriteria.
- Point values or weights.
- Responsiveness requirements.
- Programmatic considerations.
- Selection factors.
- Administrative review factors.

Distinguish scored criteria from program priorities, eligibility rules, and general advice.

### Step 4: Build the section-to-criteria crosswalk

Map each review criterion to the proposal section or sections where the applicant should address it.

Use a table:

| Review criterion | Weight or points | Primary section | Supporting section(s) | Evidence needed |
|---|---:|---|---|---|

If a criterion does not have an obvious location, identify the ambiguity and recommend where to address it. Label the placement as a recommendation rather than a sponsor requirement.

Confirm that every published review criterion appears at least once in the crosswalk.

### Step 5: Allocate the page budget

When the sponsor provides component-level limits, preserve those exact limits.

When the sponsor provides one combined narrative limit but does not allocate pages by section:

- Create a suggested page budget.
- Label it **Recommended page allocation**, not a sponsor requirement.
- Allocate space according to review weights, complexity, and evidence needs.
- Leave reasonable space for transitions, figures, tables, and references when allowed.
- Do not exceed the sponsor's total page limit.

If no page, word, or character limit is identified, state:

> **Not identified in the available authoritative sources.**

Do not invent a limit.

### Step 6: Create the editable outline

For each sponsor-required section, include:

#### [Exact Sponsor Section Title]

- **Sponsor requirement:** Concise verified summary.
- **Limit and format:** Verified page, word, character, or formatting rule.
- **Review criteria addressed:** Applicable criterion or criteria.
- **Purpose of this section:** What the section must accomplish.
- **Recommended content:** Ordered bullets describing what to include.
- **Evidence needed:** Data, citations, rationale, partner input, prior work, or institutional information required.
- **Questions for the project team:** Specific questions needed to complete the section.
- **Placeholders:** Clearly labeled missing information.
- **Source:** Official document and section or page.

Keep sponsor requirements separate from recommendations.

### Step 7: Add project-specific content only from supplied facts

Use project facts provided by the user to populate the outline. Preserve the user's intended emphasis and terminology.

Do not invent:

- Preliminary data.
- Results.
- Citations or references.
- Publications.
- Personnel names, roles, or credentials.
- Facilities or equipment.
- Institutional capabilities.
- Partner commitments.
- Letters of support.
- Prior funding or award history.
- Human-subject or animal approvals.
- Cost sharing.
- Budget figures.
- Institutional identifiers.

Use placeholders such as:

- **[PLACEHOLDER: Describe the unmet need and provide supporting evidence.]**
- **[PLACEHOLDER: Insert verified preliminary result.]**
- **[PLACEHOLDER: Add peer-reviewed citation.]**
- **[PLACEHOLDER: Confirm partner role and obtain approval.]**
- **[PLACEHOLDER: Insert current FSU institutional information from an authoritative source.]**
- **[PLACEHOLDER: Confirm budget assumption with departmental grants staff.]**

### Step 8: Integrate sponsor priorities without overstating fit

Show where the proposal may address:

- Program purpose.
- Named priorities.
- Target populations.
- Required outcomes.
- Broader impacts or public value.
- Training, workforce, dissemination, sustainability, or implementation goals.

Do not insert sponsor buzzwords without a substantive connection to the project.

Do not claim that the project addresses a priority unless the supplied project facts support the claim.

### Step 9: Identify high-risk sections

Flag sections likely to require early work, including:

- Specific aims or objectives.
- Theory of change or conceptual framework.
- Methods or work plan.
- Evaluation plan.
- Data-management or sharing plan.
- Mentoring or training plan.
- Management and governance plan.
- Community engagement plan.
- Sustainability or dissemination plan.
- Subaward scope.
- Cost-share justification.
- Letters of commitment.
- Facilities and institutional resources.

For each high-risk section, explain why it deserves early attention and identify the responsible role when known.

### Step 10: Identify attachments and non-narrative dependencies

Create a separate checklist for required attachments and forms.

For each item, identify:

- Requirement.
- Condition that triggers it.
- Responsible role.
- Information or approval needed.
- Source.

Examples may include:

- Biosketches or CVs.
- Current and pending or other support.
- Letters of support or commitment.
- Subrecipient documents.
- Data-management plans.
- Mentoring plans.
- Facilities and resources.
- Budget and justification.
- Certifications.
- Organizational documents.
- Collaborator information.

Do not mark a common attachment as required unless the current source requires it.

### Step 11: Add FSU-specific notes cautiously

Consult `01_fsu_routing.md` for routing and institutional boundaries.

Add FSU notes only when relevant, such as:

- Obtain current institutional facts from the FSU Facts Sheet.
- Confirm budget assumptions with departmental grants staff.
- Check FSU limited-submission status.
- Route public or private funding through the appropriate FSU office.
- Consult the responsible compliance office for projects involving regulated activities.
- Confirm authorized institutional language before finalizing commitments.

Do not draft or promise institutional commitments, cost share, space, personnel, approvals, or certifications.

### Step 12: Perform completeness checks

Before returning the outline, confirm that:

- Every required sponsor section appears.
- Every review criterion maps to at least one section.
- Every page or character limit is tied to the correct component.
- Required attachments are listed.
- Conditional items are labeled with their trigger.
- Sponsor requirements and recommendations are distinguishable.
- Missing facts are represented by placeholders.
- No invented project or institutional facts appear.

## Required labels

Use these labels consistently:

- **Sponsor Required**
- **FSU Required**
- **Recommendation**
- **Conditional Requirement**
- **Unknown or Unresolved**
- **PLACEHOLDER**

When a consequential fact cannot be established, state:

> **Not identified in the available authoritative sources.**

## Drafting boundaries

Do not produce polished narrative that presents unsupported project facts as true.

When the user requests drafting in addition to an outline:

1. Draft only from supplied facts.
2. Keep unsupported content as labeled placeholders.
3. Preserve sponsor headings and limits.
4. Tie draft sections to review criteria.
5. Identify factual statements that require verification.
6. Do not create citations or preliminary results.

## Failure and fallback behavior

If the official solicitation cannot be retrieved:

1. Create only a provisional outline from verified available material.
2. State that the structure and requirements require verification.
3. Ask the user for the current official solicitation or relevant attachment only when necessary.
4. Do not reconstruct requirements from a prior cycle or similar program.

If the review criteria cannot be identified:

- Complete the verified application structure.
- State that review criteria were not identified.
- Do not invent a crosswalk or weights.

If page limits conflict across sources:

1. Identify the conflict.
2. Prefer the controlling amendment or program-specific instruction.
3. Label unresolved limits clearly.
4. Recommend sponsor or FSU verification before drafting to the limit.

## Boundaries

Do not:

- Guarantee that the outline is complete without verifying current sources.
- Invent sponsor requirements, page limits, review criteria, or attachments.
- Invent research results, citations, personnel, partners, facilities, or commitments.
- Approve eligibility, budgets, compliance, cost share, or submission.
- Present recommendations as sponsor or FSU requirements.
- Treat an old successful proposal as current instruction.
- Draft institutional commitment language without authorized FSU input.
- Claim that an outlined or drafted proposal is submission-ready.

## Final quality check

Before responding, confirm that:

- The current official source and version were identified or the limitation was stated.
- Every required section appears in the outline.
- Every review criterion maps to at least one section.
- Page and formatting limits are tied to the correct component.
- Required and conditional attachments are listed.
- Sponsor requirements, FSU requirements, and recommendations are separated.
- Missing facts appear as explicit placeholders.
- No citations, personnel, results, facilities, commitments, approvals, or institutional facts were invented.
- The response ends with three specific next actions.
